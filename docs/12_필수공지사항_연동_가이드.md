# 필수 공지사항 및 대회접수 연동 개발 가이드 (어드민 & 프론트엔드 에이전트 필독)

이 문서는 백엔드(D1 및 `ybbf-api-worker`)에 배포 완료된 다기능 필수 공지사항(`notices`) API를 활용하여, **어드민 관리자 페이지**와 **사용자 프론트엔드 대회 접수 화면**을 완벽하게 구현하기 위한 클라이언트용 상세 연동 명세서입니다.

---

## 1. 데이터베이스 스키마 및 API 규격 요약

타겟 테이블: `notices` (D1 데이터베이스)
백엔드 API 주소: `https://ybbf-api-worker.jbkim.workers.dev/api` (로컬 개발 환경: `http://localhost:4300/api`)

### 1.1. 데이터 스키마 명세
백엔드에서 GET 요청 시 반환되는 Notice 객체 구조는 다음과 같습니다:

```typescript
interface Notice {
  id: string;          // 고유 ID (UUID 또는 임의의 문자열)
  title: string;       // 공지 제목
  content: string;     // 상세 본문 (HTML / Markdown 지원)
  videoUrl: string;    // 직접 업로드한 비디오 URL (MP4 등)
  youtubeUrl: string;  // 유튜브 비디오 URL
  audioUrl: string;    // 직접 업로드한 오디오 URL (MP3 등)
  images: string[];    // 다중 이미지 URL 배열 (백엔드가 JSON 파싱하여 반환)
  attachments: {       // 다운로드 첨부 파일 배열 (백엔드가 JSON 파싱하여 반환)
    name: string;      // 파일명 (예: "대회규정.pdf")
    url: string;       // 다운로드 URL
  }[];
  isMandatory: boolean; // 필수 공지 여부 (true/false)
  views: number;       // 조회수 (상세조회 시 자동 1 증가)
  sortOrder: number;   // 정렬 순서 (오름차순)
  createdAt: string;   // 생성일시
}
```

### 1.2. API 엔드포인트 명세

| Method | Endpoint | Auth | 설명 |
| :--- | :--- | :---: | :--- |
| **GET** | `/api/notices` | X | 공지사항 전체 목록 조회. `?mandatory=true` 사용 시 필수 공지만 필터링. |
| **GET** | `/api/notices/:id` | X | 개별 공지사항 상세 조회. 호출 시 자동으로 `views`가 1 증가함. |
| **POST** | `/api/admin/notices` | Admin | 신규 공지사항 생성. `images`와 `attachments`는 JSON 객체/배열 그대로 전송 가능. |
| **PUT** | `/api/admin/notices/:id` | Admin | 기존 공지사항 수정. |
| **DELETE**| `/api/admin/notices/:id` | Admin | 공지사항 삭제. |

> [!NOTE]
> 관리자 API(`POST`/`PUT`/`DELETE`) 요청 시에는 쿠키 세션 또는 헤더에 **`Authorization: Bearer <session_token>`**을 반드시 실어서 보내야 하며, 해당 계정이 `roles: "admin"` 역할을 지니고 있어야 합니다.

## 2. ⚙️ 어드민 에이전트 구현 지침 (NoticeManagerPage.tsx)

관리자가 접수 전 필수 공지사항을 생성하고 리소스를 업로드할 수 있도록 관리자 대시보드에 아래 가이드를 준수하여 구현해 주십시오.

### 2.1. 파일 및 라우팅 경로
- **위치**: `admin/src/pages/NoticeManagerPage.tsx` 생성
- **기능**: 공지사항 CRUD 테이블, 등록/수정 모달(또는 별도 폼 페이지)

### 2.2. 파일 업로드 연동 방법 (R2 스토리지)
- 동영상, 사진, 오디오, 첨부파일 등 모든 파일은 미디어 워커의 업로드 API를 사용해 R2 버킷에 저장하고 반환된 주소를 사용합니다.
- **업로드 엔드포인트**: `POST https://ybbf-media-worker.jbkim.workers.dev/api/upload` (또는 로컬 개발 `http://localhost:4400/api/upload`)
- **업로드 방식**: `multipart/form-data` 형식으로 요청하며, 목적에 따라 다음과 같이 구성합니다.
  - `file` — 업로드할 파일 (File 객체, **필수**)
  - `folder` — R2 내의 저장 폴더명 (예: `notices` 등, **공지사항 등 범용 업로드 시 사용 권장**)
  - `playerUid` — 기존 선수 사진과의 구분을 위한 선수 식별자 (문자열, **선수 사진 업로드 시에만 사용**)
- **R2 저장 경로 및 하위 호환성 규칙**:
  - **선수 사진 업로드 시**: `playerUid`를 담아서 요청하면 기존처럼 `player_photos/${playerUid}_${파일명}` 경로로 안전하게 저장되어 기존 접수 시스템과 완벽하게 호환됩니다.
  - **공지사항 등 일반 리소스 업로드 시**: `playerUid` 없이 `folder`에 **`notices`**를 담아 요청하면 `${folder}/${timestamp}_${파일명}` 경로에 고유하게 저장됩니다.
  ```typescript
  // 업로드 예시 (어드민에서 공지사항 리소스 업로드 시)
  const formData = new FormData();
  formData.append('file', selectedFile);
  formData.append('folder', 'notices'); // 공지사항용 폴더 지정 (playerUid는 불필요)

  const res = await fetch(`${VITE_MEDIA_API_URL}/api/upload`, {
    method: 'POST',
    body: formData,
  });
  const { url } = await res.json(); // R2에 저장된 파일의 서빙 URL 반환
  ```
- **주의 사항**: `notices` 등록/수정 API 요청 전, 파일 업로드를 선행하여 얻어온 URL 주소들을 `videoUrl`, `images`, `attachments`에 매핑해야 합니다.

### 2.3. 어드민 입력 폼 컴포넌트 설계 요령
1. **필수 여부 지정**: `isMandatory` 필드는 직관적인 **Toggle Switch** 또는 **Checkbox**로 제공하십시오.
2. **다중 이미지 업로드**:
   - 관리자가 여러 장의 설명 카드(이미지)를 순서대로 추가할 수 있게 지원합니다.
   - 업로드 완료된 순서에 따라 이미지 URL 배열 `string[]`을 구성하고, 최종 요청 바디의 `images` 필드에 그대로 보냅니다.
3. **첨부파일 관리**:
   - 다운로드받을 문서 리스트를 관리하기 위해 `name`(파일명)과 `url`(업로드된 주소) 세트를 하나의 행으로 하는 리스트 추가/제거 컨트롤을 구축하십시오.
   - 최종적으로 `{ name: string, url: string }[]` 구조의 배열을 `attachments` 필드로 전달합니다.
4. **비디오 화면비 해시 우회 팁**:
   - 비디오 파일이 **세로형(9:16비율, 숏폼 등)**일 경우, 주소 끝에 `#vertical` 해시 마커를 붙여서 저장하도록 권장합니다. (예: `videoUrl = uploadUrl + '#vertical'`)
   - 이렇게 저장하면 프론트엔드가 이를 감지하여 비디오 플레이어의 레이아웃을 세로형 비율로 동적 변경할 수 있습니다.

## 3. 📱 프론트엔드 에이전트 구현 지침 (RegistrationPhase.tsx)

대회 접수 단계 진입 시, 선수들에게 동의/시청해야 하는 필수 공지가 있는지 판독하고, 모든 조건을 완수하기 전에는 정보 입력 단계로 넘어가지 않도록 멀티 스텝(Multi-step) 구조 내에 연동하십시오.

### 3.1. 대회 접수 진입 프로세스 흐름 (Multi-step 구조 통합)
1. 접수 페이지 진입 시 `GET /api/notices?mandatory=true`를 호출하여 필수 공지 리스트를 수집합니다.
2. 필수 공지가 없다면 원래의 기본 접수 단계(`activeSteps = ['info', 'joins', 'pledge', 'confirm']`)를 적용하여 'info'(인적 사항 입력) 단계부터 시작합니다.
3. 필수 공지가 한 개 이상 존재하면, 접수 단계의 첫머리에 `'notice'` 단계를 주입합니다 (`activeSteps = ['notice', 'info', 'joins', 'pledge', 'confirm']`).
4. **`notice` 단계 제어**:
   - `currentStepId === 'notice'`일 때, `mandatoryNotices` 배열의 공지사항을 첫 번째(`currentNoticeIndex = 0`)부터 차례대로 화면에 렌더링합니다.
   - 각 공지별 검증 요건(본문 스크롤 하단 도달, 필수 동영상 시청 완료, 카드 뉴스 확인 등)이 충족되면 다음 공지로 넘어가는 버튼 또는 `'info'` 단계로 진행 가능한 버튼을 활성화합니다.
   - 모든 필수 공지의 동의를 완료하면 `goToNextStep()`을 호출하여 비로소 인적 사항(`'info'`) 단계로 진입시킵니다.

### 3.2. 정독 검증: 스크롤 끝(Scroll-to-Bottom) 감지
글로 작성된 공지사항의 본문(`content`)을 선수가 끝까지 마우스를 내려 읽었는지 확인하는 React 컴포넌트 예시입니다. 반드시 프로젝트 디자인 시스템에 맞게 리스타일링하여 구현하십시오.

```tsx
import React, { useRef, useState, useEffect } from 'react';

interface NoticeScrollReaderProps {
  content: string; // HTML 혹은 마크다운 본문
  onReadComplete: () => void; // 스크롤 완독 시 콜백
}

export function NoticeScrollReader({ content, onReadComplete }: NoticeScrollReaderProps) {
  const containerRef = useRef<HTMLDivElement>(null);
  const [isReadComplete, setIsReadComplete] = useState(false);

  const handleScroll = () => {
    const el = containerRef.current;
    if (!el || isReadComplete) return;

    // scrollHeight(전체 높이) - scrollTop(스크롤 위치) <= clientHeight(보이는 높이) + 오차마진(5px)
    const isBottom = el.scrollHeight - el.scrollTop <= el.clientHeight + 5;

    if (isBottom) {
      setIsReadComplete(true);
      onReadComplete();
    }
  };

  useEffect(() => {
    // 본문 변경 시 완료 상태 초기화
    setIsReadComplete(false);
    
    // 컴포넌트 렌더링 후, 만약 본문이 짧아 스크롤바가 생성되지 않는 경우 즉시 완독 처리
    const timer = setTimeout(() => {
      const el = containerRef.current;
      if (el && el.scrollHeight <= el.clientHeight) {
        setIsReadComplete(true);
        onReadComplete();
      }
    }, 200);

    return () => clearTimeout(timer);
  }, [content]);

  return (
    <div
      ref={containerRef}
      onScroll={handleScroll}
      className="max-h-[350px] overflow-y-auto border border-[#E2E8F0] p-5 rounded-lg bg-[#F8FAFC] leading-relaxed text-[#334155]"
      dangerouslySetInnerHTML={{ __html: content }}
    />
  );
}
```

### 3.3. 시청 검증: 동영상 재생 완료 확인
공지에 비디오나 유튜브 주소가 포함되어 있을 시, 사용자가 영상을 끝까지 시청했는지 확인하여 락을 제어합니다.

#### 1) 직접 업로드된 비디오 (`videoUrl` 사용 시)
HTML5 `<video>` 요소의 `onEnded` 이벤트를 바인딩해 간편하게 감지하십시오.
```tsx
const [videoWatched, setVideoWatched] = useState(false);

return (
  <video
    src={notice.videoUrl}
    controls
    onEnded={() => {
      setVideoWatched(true);
      checkNoticeVerification();
    }}
    className="w-full rounded-lg shadow-sm"
  />
);
```

#### 2) 유튜브 동영상 (`youtubeUrl` 사용 시)
유튜브 iframe을 연동할 때는 YouTube IFrame Player API를 로드하여 재생이 끝났는지를 판독해야 합니다. 
대안으로, 선수가 영상을 스킵하고 닫는 꼼수를 막기 위해 유튜브 동영상 렌더링 시 **"재생 시점부터 영상 길이만큼 타이머 대기"** 또는 **"재생 종료 이벤트 감지 리스너"**를 구성해 주십시오.

### 3.4. 비디오 화면비(Aspect Ratio) 렌더링 가이드
- 비디오 URL이나 유튜브 주소 뒤에 `#vertical` 해시 마커가 붙어 있거나, 유튜브 shorts 링크(`youtube.com/shorts/`) 형식인 경우에는 비디오 플레이어 영역을 세로형으로 축소하여 렌더링하십시오.
- **권장 Tailwind 클래스(CSS)**: `aspect-[9/16] max-w-[320px] mx-auto`
- 일반 가로형 비디오의 경우: `aspect-[16/9] w-full`

### 3.5. 다중 사진 및 첨부문서 렌더링 가이드
- **다중 사진 (`images`)**: 카드 형식의 규칙 이미지나 카드뉴스가 등록되어 있다면 슬라이드 캐러셀(Carousel) 형태로 좌우 스와이프하며 정독할 수 있도록 렌더링해 주십시오.
- **첨부 문서 (`attachments`)**: 참가 가이드나 공식 PDF 규정 서류가 첨부되어 있을 경우, 이를 예쁜 다운로드 다운박스/버튼 카드로 가시성 있게 노출하여 유저가 터치 시 브라우저에서 다운로드 또는 미리보기가 구동되게 배치하십시오.

## 4. UI/UX 및 디자인 핵심 원칙 (모든 에이전트 공통)

1. **정돈된 레이아웃 & 가시성**:
   - 필수 공지사항 화면은 일반적인 팝업 창보다 **전면 오버레이(Full-screen overlay modal)**로 구성하는 것이 사용자의 시선을 집중시키기에 적합합니다.
   - 회색이나 연한 파스텔톤 계열의 배경을 활용하여 텍스트 가독성을 최대로 높여 주십시오.
2. **동작 유도(Call-to-Action) 버튼 상태 전환**:
   - 스크롤을 끝까지 내리고 미디어를 다 볼 때까지 "확인/동의 완료" 버튼은 `disabled` 상태로 반투명 처리하고 비활성화 상태여야 합니다.
   - 모든 검증이 끝나면 버튼에 **그라데이션 효과** 또는 **바운스 애니메이션**과 같은 시각적 변화를 주어 사용자가 완료되었음을 확실히 체감할 수 있도록 개발해 주십시오.
