# YBBF 관리자 시스템 백엔드 API 및 DB 스키마 요청서

본 문서는 YBBF(용인시보디빌딩협회) 플랫폼의 관리자 대시보드 연동을 위해 필요한 백엔드(Cloudflare Workers & D1 & R2) API 및 데이터베이스 요구사항 명세서입니다.

---

## 1. 데이터베이스 스키마 요구사항

### 1.1. 시스템 설정 전용 테이블 (`system_settings` 신설)
현재 프론트엔드의 세팅 정보(히어로 선수 스탯, 대문 이미지 주소, 대회 정보, 계좌 번호 등)를 동적으로 관리하기 위해 Cloudflare D1에 설정을 전용으로 저장하는 단일 테이블 신설을 요청합니다.
(※ `virtual_kv`는 로컬 개발을 위해 임시로 제공되는 가상 스택이므로 사용하지 마십시오.)

#### D1 SQL 스키마
```sql
CREATE TABLE IF NOT EXISTS system_settings (
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL,
  updatedAt TEXT DEFAULT CURRENT_TIMESTAMP
);
```

- **Key**: `system_settings`
- **Value**: 시스템 설정 전체를 묶은 JSON 문자열
- **JSON 포맷 예시**:

## 2. API 엔드포인트 명세

모든 관리자 전용 API는 요청 헤더의 `Cookie`에 포함된 `session_token`(사용자 `uid` 값)을 검증하여, 해당 사용자의 역할군(`roles`)에 `admin`이 포함되어 있는지를 먼저 판단해야 합니다. (비관리자 접근 시 `403 Forbidden` 반환)

### 2.1. 시스템 설정 API

#### ① 설정 정보 조회 (비로그인/일반사용자도 호출 가능)
- **엔드포인트**: `GET /api/settings`
- **응답 (200 OK)**:
  - 설정 데이터 반환 (데이터가 비어있는 경우 내장된 디폴트 설정 객체를 반환)
  - 응답 바디: 상기 1.1에 기술한 JSON 형식

#### ② 설정 정보 업데이트 (관리자 전용)
- **엔드포인트**: `POST /api/settings`
- **요청 바디**: 시스템 설정 JSON 객체
- **인증 필요**: `session_token` 쿠키 검증 및 `admin` 권한 체크 필수.
- **응답 (200 OK)**:
  ```json
  { "success": true, "message": "설정이 성공적으로 저장되었습니다." }
  ```

---

### 2.2. 회원 관리 API (관리자 전용)

#### ① 전체 회원 목록 조회 (복호화 포함)
- **엔드포인트**: `GET /api/admin/users`
- **인증 필요**: `session_token` 쿠키 검증 및 `admin` 권한 체크 필수.
- **처리 로직**:
  1. `users` 테이블 전체 조회.
  2. `user_profiles` 테이블 조인.
  3. `user_profiles`에 저장된 민감 정보(`name`, `tel` 필드)를 복호화 알고리즘(`AES-256-GCM` 및 `CRYPTO_SECRET` 환경 변수 사용)을 가동해 평문으로 변환.
  4. 보안 필드(`passwordHash`, `salt` 등)를 제거하여 안전한 객체 배열로 반환.
- **응답 (200 OK)**:
  ```json
  [
    {
      "uid": "user-uuid-1",
      "email": "user1@example.com",
      "provider": "email",
      "profileComplete": true,
      "roles": ["user", "athlete"],
      "profile": {
        "name": "홍길동",   /* 복호화 완료된 평문 */
        "birth": "1995-05-10",
        "tel": "010-1234-5678", /* 복호화 완료된 평문 */
        "gym": "용인 헬스클럽",
        "gender": "m"
      }
    }
  ]
  ```

#### ② 회원 역할군(권한) 변경
- **엔드포인트**: `POST /api/admin/users/:uid/roles`
- **인증 필요**: `session_token` 쿠키 검증 및 `admin` 권한 체크 필수.
- **요청 바디**:
  ```json
  {
    "roles": ["user", "admin"]
  }
  ```
- **처리 로직**: 해당 `uid`를 가진 사용자의 `roles`를 업데이트합니다. (D1 데이터베이스에는 쉼표 구분자 문자열 등으로 보관됨에 유의)
- **응답 (200 OK)**:
  ```json
  { "success": true, "message": "역할군 변경이 완료되었습니다." }
  ```

#### ③ 회원 강제 탈퇴 (삭제)
- **엔드포인트**: `DELETE /api/admin/users/:uid`
- **인증 필요**: `session_token` 쿠키 검증 및 `admin` 권한 체크 필수.
- **처리 로직**: 해당 `uid`의 `users` 레코드 및 외래키 연동된 `user_profiles` 데이터를 삭제합니다.
- **응답 (200 OK)**:
  ```json
  { "success": true, "message": "회원 정보가 완전히 삭제되었습니다." }
  ```

#### ④ 신규 사용자/관리자 수동 등록
- **엔드포인트**: `POST /api/admin/users`
- **인증 필요**: `session_token` 쿠키 검증 및 `admin` 권한 체크 필수.
- **요청 바디**:
  ```json
  {
    "email": "newadmin@ybbf.org",
    "password": "securepassword",
    "roles": ["user", "admin"],
    "profile": {
      "name": "관리자이름",
      "birth": "1990-01-01",
      "tel": "010-0000-0000",
      "gym": "협회본부",
      "gender": "m"
    }
  }
  ```
- **처리 로직**: 새로운 사용자를 추가하고 비밀번호를 해싱하여 등록합니다. 프로필 정보가 입력된 경우 양방향 암호화를 수행하여 적재합니다.
- **응답 (200 OK)**:
  ```json
  { "success": true, "message": "사용자 등록이 완료되었습니다." }
  ```

## 3. 세션 검증 및 보안 검토사항

1. **로그인 권한 검증 구현**:
   - `getCookie(c, 'session_token')`로 세션 토큰을 획득하고 D1 `users` 테이블에서 해당 사용자를 찾습니다.
   - 사용자 레코드 내 `roles` 문자열(예: `"user,admin"`)을 파싱하여 `admin`이 들어있는지 무조건 체크하는 공통 유틸리티 미들웨어를 구축하여 관리자 API 경로(`* /api/admin/*`, `POST /api/settings` 등)에 일괄 적용을 요청합니다.
2. **소셜 로그인 및 어드민 최초 권한 획득에 대하여**:
   - 최초 관리자 계정이 필요한 경우, `admin@ybbf.org`로 가입/로그인 시 백엔드 단에서 자동으로 `admin` 역할군을 부여해 데이터베이스에 반영하도록 특별 가입 분기 처리를 요청드립니다.
