# 문서 관리 규칙

---

## 1. 폴더 구조

```
ybbf/
├── docs/          ← PM 전용. 기획/설계/원칙 문서 (읽기 전용)
└── worklogs/      ← 작업자용. 실제 작업 기록 (자유 편집)
```

## 2. `docs/` 규칙

- **편집 권한**: PM만 편집 가능
- **절대 수정/삭제 금지**: AI 작업자는 docs 문서를 **참조만** 한다
- **목적**: 기획, 설계, 디자인 원칙, 로드맵 등 **변하지 않는 기준 문서**
- **추가**: PM이 필요할 때만 새 문서를 추가하거나 기존 문서를 수정

## 3. `worklogs/` 규칙

- **편집 권한**: 작업자(AI 포함) 자유 편집
- **문서 생성 방식**:
  1. docs 문서의 체크리스트나 태스크를 **복사**하여 새 문서로 생성
  2. 연번을 달아서 관리: `001_`, `002_`, `003_` ...
  3. 작업 진행 상황, 완료 여부, 메모 등을 자유롭게 기록
- **네이밍 규칙**: `{연번}_{작업내용}.md`
  - 예: `001_Phase0_인프라_세팅.md`
  - 예: `002_레전드_페이지_구현.md`
  - 예: `003_반응형_QA.md`

## 4. 작업 흐름

```
1. PM이 docs/ 에 기획 문서를 작성한다
2. 작업자가 docs/ 를 읽고 이해한다 (수정 금지)
3. 작업자가 worklogs/ 에 새 문서를 만든다
   - docs의 체크리스트를 복사해 와서 시작
   - 작업하면서 완료 체크, 메모, 이슈 기록
4. 작업 완료 후 worklogs 문서에 결과를 정리한다
5. PM이 필요시 docs를 업데이트한다
```

## 5. 예시

`docs/05_구현_로드맵.md`의 Phase 0 작업을 시작할 때:

```
worklogs/001_Phase0_인프라_세팅.md 생성
↓
docs/05_구현_로드맵.md의 Phase 0 체크리스트를 복사
↓
작업하면서 체크 표시 + 메모 추가
↓
완료 후 결과 요약 작성
```
