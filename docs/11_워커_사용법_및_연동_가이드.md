# YBBF 워커 사용법 및 연동 가이드 (개발자용)

본 문서는 YBBF(용인시보디빌딩협회) 플랫폼의 백엔드를 담당하는 3개의 Cloudflare Workers(인증, 일반 API, 미디어)의 역할 정의, 로컬 개발 환경 실행 방법, 보안 아키텍처 및 프론트엔드/관리자 대시보드 연동 규격을 설명하는 개발자용 가이드북입니다.

---

## 1. 백엔드 아키텍처 및 워커 역할 정의

YBBF의 백엔드는 모노레포 구조 아래 각 도메인의 독립성과 보안 정합성을 보장하기 위해 3개의 마이크로 워커로 분할되어 있습니다.

| 워커명 | 기본 포트 (로컬) | 배포 URL | 주요 역할 및 담당 도메인 |
| :--- | :---: | :--- | :--- |
| **`ybbf-auth-worker`** | `4200` | `https://ybbf-auth-worker.jbkim.workers.dev` | 회원가입, 로그인, 로그아웃, 회원 추가정보 등록, 비밀번호 재설정 코드 발송, 세션 확인 |
| **`ybbf-api-worker`** | `4300` | `https://ybbf-api-worker.jbkim.workers.dev` | 시스템 설정(Hero 및 대회정보), 대회 접수 정보 D1 아카이빙, 대회 알림 신청, 명예의 전당 레전드 CRUD, 유스 양성 시스템(클럽/선수/경력) CRUD, 관리자용 회원 정보 관리 |
| **`ybbf-media-worker`**| `4400` | `https://ybbf-media-worker.jbkim.workers.dev` | 메인/서브페이지 공식 미디어 아카이브 데이터 조회, 관리자용 미디어 CRUD 일원화, 선수 프로필 사진 등 R2 미디어 파일 업로드 및 이미지 프록시 서빙 전담 |

---

## 2. 로컬 개발 환경 기동 방법 (원격 자원 연동)

모든 워커는 로컬 개발 환경(`wrangler dev`) 구동 시에도 로컬 모크 데이터나 가상 환경이 아닌 **실제 Cloudflare D1 데이터베이스(`ybbf_db`)와 R2 버킷(`ybbf-storage`)을 실시간으로 호출**하도록 `--remote` 플래그로 연동되어 있습니다. 
따라서 로컬에서 작업한 데이터 변경 사항이 실시간으로 원격 D1/R2에 직접 반영됩니다.

### 2.1. 개발 서버 실행 명령어

최상위 루트 디렉토리에서 npm workspaces 명령어를 통해 각 워커를 독립 기동합니다.

```bash
# 1. 인증 워커 실행 (포트 4200)
npm run dev -w workers/auth

# 2. 비즈니스 API 워커 실행 (포트 4300)
npm run dev -w workers/api

# 3. 미디어 워커 실행 (포트 4400)
npm run dev -w workers/media
```

## 3. 프론트엔드 및 관리자 페이지 환경 변수 설정

프론트엔드 및 관리자 대시보드 개발 환경에서는 연동할 API URL 주소를 각 도메인 영역별로 명확하게 분리 지정해 주어야 합니다.

### 최상위 `.env` 설정 예시

```env
# [개발 환경 (Localhost)]
# VITE_AUTH_API_URL="http://localhost:4200"
# VITE_BACKEND_API_URL="http://localhost:4300"
# VITE_MEDIA_API_URL="http://localhost:4400"

# [운영 및 배포 환경 (Cloudflare Workers)]
VITE_AUTH_API_URL="https://ybbf-auth-worker.jbkim.workers.dev"
VITE_BACKEND_API_URL="https://ybbf-api-worker.jbkim.workers.dev"
VITE_MEDIA_API_URL="https://ybbf-media-worker.jbkim.workers.dev"
```

## 4. 인증 및 보안 검증 메커니즘

### 4.1. 쿠키 기반 세션 토큰 검증
- 사용자가 로그인에 성공하면, 백엔드는 브라우저 쿠키에 `session_token`(사용자의 고유 `uid` 평문 값)을 `HttpOnly`, `Secure`, `SameSite=None` 속성으로 발급합니다.
- 프론트엔드는 모든 API 호출 시 `credentials: 'include'` 옵션을 동봉하여 쿠키가 백엔드에 자동으로 전달되도록 처리해야 합니다.
- **SameSite=None & Secure 적용 사유**: 프론트엔드(`http://localhost:4100`)와 백엔드 워커(`https://*.workers.dev`) 간의 도메인이 달라 발생하는 크로스 사이트(Cross-Site) 쿠키 전송 차단 문제를 해결하고, 로컬 연동 개발과 실서버 배포 시 세션 정합성을 일치시키기 위해 `SameSite=None` 및 `Secure` 쿠키 정책을 적용했습니다.
- **CORS 허용 정책**: 로컬 개발 시 여러 포트(포트 4100 프론트엔드, 4500 어드민 등)로부터 들어오는 비동기 요청과 쿠키 공유를 위해, `http://localhost`로 시작하는 모든 Origin에 대해 CORS 허용 및 자격 증명 전송(`credentials: true`)을 동적으로 지원하도록 워커 미들웨어가 설계되어 있습니다.
- **Authorization 헤더 지원 (하이브리드 인증)**: `*.workers.dev` 서브도메인 간(예: `auth-worker`와 `api-worker`) 쿠키 공유를 차단하는 브라우저의 도메인 정책을 우회하기 위해, 백엔드 미들웨어는 `Cookie` 세션 유무 외에도 **`Authorization: Bearer <session_token>`** 헤더를 통한 토큰 파싱을 정식 지원합니다. 클라이언트는 로그인 시 취득한 `uid`를 로컬스토리지에 저장한 뒤 요청 헤더에 실어 통신합니다.

### 4.2. 관리자 전용 미들웨어 (`adminMiddleware`)
- `/api/admin/*` 경로 및 설정 업데이트(`POST /api/settings`) 등 관리자 권한이 요구되는 API는 백엔드 내 공통 미들웨어가 쿠키를 파싱합니다.
- D1 데이터베이스의 `users` 테이블에서 해당 `uid` 레코드의 `roles` 필드를 조회하여, `"admin"` 역할군이 들어있는지 강제 검증합니다. 비관리자 접근 시 `403 Forbidden`을 반환합니다.

### 4.3. 최초 관리자 권한 획득 규칙 (`admin@ybbf.org`)
- 시스템 초기 가동 단계나 데이터베이스가 비어있는 상태에서 관리자 권한을 최초 획득하기 위해 특별 우회 룰이 적용되어 있습니다.
- **이메일 주소가 `admin@ybbf.org`인 사용자가 회원가입/로그인을 시도할 경우, 백엔드 로직이 이를 감지하여 자동으로 `roles` 필드에 `admin` 권한을 지정 및 복구**하여 적재합니다.

## 5. 3단계 암호화 격리 구조 및 복호화 가이드

유저 정보의 기밀성을 보호하기 위해 `D1 / KV / CRYPTO_SECRET`를 조합한 3단계 격리 보안 구조가 수립되어 있습니다.

1. **비밀번호 단방향 해싱 (PBKDF2-SHA512)**:
   - 가입 시 고유 16바이트 솔트(Salt)를 난수 생성하여 실제 Cloudflare KV Namespace (`KV` 바인딩)에 유저별로 안전하게 격리 보관합니다.
   - 비밀번호 + 솔트 + `CRYPTO_SECRET` (서버 환경변수 페퍼 키)을 조합하여 단방향 해싱 후 적재합니다.
2. **프로필 양방향 암호화 (AES-256-GCM)**:
   - 프로필 중 민감 정보인 **이름(`name`)과 전화번호(`tel`)**는 서버 시크릿 키(`CRYPTO_SECRET`)를 대칭키로 사용하여 암호화하여 저장합니다.
   - 단, 평문 형태의 전화번호 뒤 4자리(`telLast4`)를 인덱스용으로 추가 보관하여 이름/번호 끝자리 기반의 유저 매칭 검색 속도를 최적화합니다.
3. **관리자 조회 시 복호화 서비스**:
   - 관리자가 전체 회원 목록(`GET /api/admin/users`)을 조회하는 경우, 백엔드는 D1의 암호화된 `name`과 `tel` 컬럼을 내부에서 자동으로 복호화하여 평문 텍스트 객체로 변환하여 반환합니다. (즉, 관리자 페이지 개발자는 복호화 처리를 따로 할 필요 없이 바로 화면에 뿌려줄 수 있습니다.)

## 6. 주요 API 명세 요약

### 6.1. 인증 워커 (`ybbf-auth-worker`) 주요 APIs

- **`POST /api/auth/signup`**
  - 요청 바디: `{ "email": "...", "password": "..." }`
  - 설명: 회원가입 및 세션 쿠키 발급.
- **`POST /api/auth/login`**
  - 요청 바디: `{ "email": "...", "password": "..." }`
  - 설명: 로그인 및 세션 쿠키 발급. (IP 기준 5회 실패 시 60초 락아웃 제어 포함)
- **`GET /api/auth/me`**
  - 설명: 세션 쿠키 기반의 현재 로그인 사용자 정보 확인.
- **`POST /api/auth/logout`**
  - 설명: 발급된 세션 쿠키 폐기 및 로그아웃.
- **`POST /api/auth/additional-info`**
  - 요청 바디: `{ "name": "...", "birth": "...", "tel": "...", "gym": "...", "gender": "..." }`
  - 설명: 회원 프로필 추가 정보 암호화 저장.

### 6.2. 일반 API 워커 (`ybbf-api-worker`) 주요 APIs

- **`GET /api/settings`** (비로그인 허용)
  - 설명: 메인 비주얼, 대회 일정, 계좌 정보 등 시스템 설정 조회. (D1에 설정이 비어있는 경우 디폴트 템플릿 반환)
  - **설정 스키마 개편**: 메인 화면 히어로 영역에 다중 우승자 롤링/랜덤 표시를 지원하기 위해 `heroPlayers` 배열 구조가 새로 정립되었습니다. 기존 `heroDDay` 및 `heroConditioning` 필드는 완전히 제거되었으며, 각 선수의 소속 체육관/협회명을 입력받는 `heroGym` 필드가 신규 도입되었습니다.
- **`POST /api/settings`** (어드민 전용)
  - 설명: 시스템 설정 JSON 일괄 업데이트. 페이로드에 포함된 다중 히어로 선수 정보가 `system_settings` 테이블의 `system_settings` 키에 통째로 직렬화(JSON)되어 영속화됩니다.
- **`GET /api/landing/sections`** (비로그인 허용)
  - 설명: 각 페이지의 섹션별 텍스트 및 이미지 경로 조회. (`?page=home`, `?page=about` 등의 쿼리 필터 지원)
- **`POST /api/landing/sections/:sectionId`** (어드민 전용)
  - 설명: 특정 페이지 섹션 내용 편집.
- **`GET /api/about/affiliations`** (비로그인 허용)
  - 설명: 협회 소개 페이지의 공인 연맹 카드 리스트 조회.
- **`POST / PUT / DELETE /api/about/affiliations`** (어드민 전용)
  - 설명: 협회 공인 연맹 카드 추가/수정/삭제.
- **`GET /api/legends`** (비로그인 허용)
  - 설명: 명예의 전당 역대 챔피언 목록 및 관련 타이틀, 갤러리 이미지 조회.
- **`POST / PUT / DELETE /api/admin/legends`** (어드민 전용)
  - 설명: 명예의 전당 레전드 프로필 등록/수정/삭제.
- **`POST / DELETE /api/admin/legends/:id/titles`** (어드민 전용)
  - 설명: 특정 레전드의 세부 대회 우승 경력 추가/삭제.
- **`GET /api/youth/athletes`** (비로그인 허용)
  - 설명: 공식 유스 클럽 및 유스 빌더(선수) Roster, 수상 실적 조회.
- **`POST / PUT / DELETE /api/admin/youth/athletes`** (어드민 전용)
  - 설명: 유스 선수 카드 등록/수정/삭제.
- **`GET /api/admin/users`** (어드민 전용)
  - 설명: 관리자용 전체 회원 목록 조회 (이름, 연락처 평문 복호화 완료 상태로 제공).
- **`GET /api/notices`** (비로그인 허용)
  - 설명: 공지사항 게시판 목록 조회. `?mandatory=true` 또는 `?mandatory=1` 쿼리를 추가하면 접수 전 필수 확인 지정 공지(`isMandatory = 1`)들만 필터링하여 제공합니다. (자동 파싱된 `images` 및 `attachments` 배열 포함)
- **`GET /api/notices/:id`** (비로그인 허용)
  - 설명: 지정된 공지사항 게시글 상세 조회 및 조회수(`views`) 1 증가 연산 처리.
- **`POST / PUT / DELETE /api/admin/notices`** (어드민 전용)
  - 설명: 다기능 공지사항 추가/수정/삭제. (동영상, 오디오, 다중 사진 이미지, 첨부 서류 리스트 등 일괄 저장)

### 6.3. 미디어 워커 (`ybbf-media-worker`) 주요 APIs

- **`GET /api/media`** (비로그인 허용)
  - 쿼리 파라미터: `category` ('highlight'/'interview'/'training'/'notice'), `featured` ('true')
  - 설명: 미디어 센터 비디오 그리드 조회.
- **`GET /api/media/:id`** (비로그인 허용)
  - 설명: 특정 미디어 세부 정보 확인.
- **`POST / PUT / DELETE /api/admin/media`** (어드민 전용)
  - 설명: 공식 미디어 센터 영상 콘텐츠 추가/수정/삭제.
  - **페이로드 및 구조**: `{ id, title, category, thumbnail, videoUrl, youtubeUrl, aspect, date, description, featured, relatedLegendIds, sortOrder }`
  - **유튜브 썸네일 자동 생성**: 유튜브 URL이 입력되었고 썸네일 주소가 공란인 경우, 백엔드에서 `https://img.youtube.com/vi/<videoId>/hqdefault.jpg` 형식으로 썸네일 주소를 자동으로 계산하여 등록/수정해 줍니다.
  - **비디오 화면 종횡비 (`aspect`)**: 가로형 영상인 경우 `"landscape"`, 세로형 영상(쇼츠 등)인 경우 `"portrait"` 값을 전달합니다. (기본값: `"landscape"`)
- **`POST /api/upload`** (비로그인 허용 - 접수 선수용)
  - 설명: 선수 프로필 사진 등 Cloudflare R2 스토리지 파일 업로드 API. 성공 시 `MEDIA_PUBLIC_URL` 환경 변수가 있으면 해당 주소를, 없으면 요청한 Host Origin 도메인을 기반으로 동적 이미지 서빙 URL을 반환합니다.
- **`GET /api/photos/*`** (비로그인 허용)
  - 설명: Cloudflare R2 스토리지 내 적재된 파일(선수 사진/비디오 등) 실시간 프록시 서빙 API. 브라우저 및 Cloudflare CDN 에지 서버가 이 리소스를 강력히 캐싱(1년)하도록 `Cache-Control: public, max-age=31536000, immutable` 헤더를 탑재하여 요금(Workers/R2 B요청)을 극적으로 절감하고 서빙 성능을 극대화합니다. (CORS credentials 지원)

## 7. 보안 환경 변수 및 시크릿(Secret) 관리 규격

프로젝트 보안 향상과 민감한 API Key 노출 방지를 위해 로컬 개발 환경과 실제 배포 환경의 시크릿 주입 방식을 격리 설계하였습니다.

### 7.1. 로컬 개발 환경용 시크릿 (`.dev.vars`)
- 로컬 환경(`wrangler dev`)에서 암호화와 메일 발송 기능이 정상 작동하도록 각 워커 폴더 루트에 `.dev.vars` 파일을 생성하여 관리합니다.
- 이 파일은 로컬 실행 시에만 wrangler가 읽어 들여 런타임에 바인딩하므로 Git 형상 관리 대상에서 제외됩니다.
- **설정 내용 (`.dev.vars` 파일 예시)**:
  ```env
  RESEND_API_KEY="re_YOUR_RESEND_API_KEY_HERE"
  CRYPTO_SECRET="YOUR_64_CHAR_HEX_CRYPTO_SECRET_HERE"
  # 로컬 개발 시 원격 D1을 연동 테스트할 때, 로컬 이미지 주소(http://localhost:4400)가 저장되어 실서버에서 엑박이 발생하는 것을 방지하기 위해 실서버 미디어 주소 지정 가능
  MEDIA_PUBLIC_URL="https://ybbf-media-worker.jbkim.workers.dev"
  ```

### 7.2. 운영(Production) 배포용 시크릿 (`wrangler secret`)
- Cloudflare 배포 환경에서는 민감 정보 노출을 방지하기 위해 `wrangler.jsonc` 내의 `vars` 영역에 평문으로 등록하는 방식을 금지하고, Cloudflare 암호화 KMS 영역인 **Secrets**로 등록합니다.
- **원격 시크릿 등록 방법 (CMD/PowerShell)**:
  ```powershell
  # 1. 인증 워커 (ybbf-auth-worker) 시크릿 등록
  cd workers/auth
  echo "YOUR_CRYPTO_SECRET" | npx wrangler secret put CRYPTO_SECRET
  echo "YOUR_RESEND_API_KEY" | npx wrangler secret put RESEND_API_KEY

  # 2. 일반 API 워커 (ybbf-api-worker) 시크릿 등록
  cd workers/api
  echo "YOUR_CRYPTO_SECRET" | npx wrangler secret put CRYPTO_SECRET
  echo "YOUR_RESEND_API_KEY" | npx wrangler secret put RESEND_API_KEY

  # 3. 미디어 워커 (ybbf-media-worker) 시크릿 등록
  cd workers/media
  echo "YOUR_CRYPTO_SECRET" | npx wrangler secret put CRYPTO_SECRET
  echo "YOUR_RESEND_API_KEY" | npx wrangler secret put RESEND_API_KEY
  ```
- **중요**: Cloudflare Workers 정책 상 `wrangler.jsonc` 파일에 평문 환경 변수(`vars`)와 동일한 명칭의 `Secret`이 존재하면 빌드 배포 단계에서 중복 오류(`Binding name already in use`)가 발생하므로, `wrangler.jsonc`의 `vars` 항목에서 두 변수를 완전히 제거해 주어야 합니다. (현재 모든 워커에 적용 완료)
