# 공통 디자인 원칙 & AI 디자인 안티패턴

> **이 문서는 모든 페이지/컴포넌트 구현 시 반드시 참조해야 하는 디자인 규칙이다.**
> AI가 코드를 생성할 때 빠지기 쉬운 함정을 사전에 차단한다.

---

## 1. AI 디자인의 대표적 문제점

### 🚫 문제 1: 카드 안에 카드 안에 카드 (과도한 중첩)

AI는 "구분"을 좋아한다. 그래서 **카드 → 그 안에 카드 → 그 안에 또 카드**를 만든다.
PC에서는 괜찮아 보이지만, 모바일에서는 패딩이 겹겹이 쌓여 **실제 콘텐츠 영역이 화면의 40%도 안 되는** 참사가 발생한다.

```
❌ 나쁜 예:
┌──────────────────────────────────┐  ← 섹션 padding 32px
│  ┌────────────────────────────┐  │  ← 카드 padding 24px
│  │  ┌──────────────────────┐  │  │  ← 내부 카드 padding 16px
│  │  │  실제 콘텐츠 (좁아!)  │  │  │
│  │  └──────────────────────┘  │  │
│  └────────────────────────────┘  │
└──────────────────────────────────┘
→ 모바일 375px 기준: 32+24+16 = 좌우 합산 144px 소모. 콘텐츠 231px만 남음.

✅ 좋은 예:
┌──────────────────────────────────┐  ← 섹션 padding 16px (모바일)
│  실제 콘텐츠 (넓다!)              │  ← 구분은 border-bottom이나 간격으로
│  ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─  │
│  다음 콘텐츠                      │
└──────────────────────────────────┘
→ 모바일 375px 기준: 좌우 합산 32px. 콘텐츠 343px 확보.
```

**규칙**: 중첩 깊이 최대 1단계. 카드 안에 카드 금지.

---

### 🚫 문제 2: 의미 없는 래퍼(Wrapper) 남발

AI는 `<div>` 안에 `<div>` 안에 `<div>`를 무의미하게 감싼다.
각 래퍼마다 padding/margin이 붙으면 공간이 증발한다.

**규칙**: 래퍼는 레이아웃 목적이 있을 때만. "혹시 몰라서" 감싸지 않는다.

---

### 🚫 문제 3: PC 기준 설계 후 모바일 축소

AI는 항상 **넓은 화면**을 먼저 그린다.
- PC에서 `padding: 64px`, `gap: 48px`로 시원하게 배치
- 모바일에서도 그대로 들어가서 콘텐츠가 **세로로 끝없이 늘어남**

**규칙**: 모바일 퍼스트. `px-4` (16px)를 기본으로 설계하고, `md:`에서 넓힌다.

---

### 🚫 문제 4: 보라색/그라디언트 카드 남용

AI가 "프리미엄" 하면 무조건 꺼내는 3종 세트:
- `bg-gradient-to-br from-purple-500 to-blue-600`
- `backdrop-blur-xl`
- `rounded-3xl shadow-2xl`

이 프로젝트는 **올블랙 + 네온 라임**이 정체성이다. 보라색은 없다.

**규칙**: 컬러는 반드시 디자인 시스템의 CSS 변수만 사용.

---

### 🚫 문제 5: 장식 요소 과잉

AI는 빈 공간을 못 참는다. 그래서 넣는 것들:
- 배경 그라데이션 원형 블러 (의미 없는 `bg-blur-circle`)
- 반투명 보더 (`border border-white/10`) 모든 요소에
- `shadow-lg shadow-purple-500/20` 글로우 효과 남발
- 장식용 아이콘을 모든 카드에

**규칙**: 장식 요소는 **히어로 섹션에만** 허용. 나머지는 콘텐츠로 승부.

---

### 🚫 문제 6: 텍스트 크기 일관성 부족

AI가 만든 페이지를 보면:
- 어떤 라벨은 `text-[10px]`, 어떤 건 `text-xs`, 또 어떤 건 `text-[11px]`
- `font-bold`, `font-black`, `font-semibold`가 랜덤으로 섞임
- `tracking-[0.2em]`, `tracking-widest`, `tracking-[0.3em]` 제각각

**규칙**: 아래 타이포 스케일을 따른다. 예외 금지.

---

## 2. YBBF 공통 디자인 토큰

### 2.1 패딩 & 간격 규칙

```
섹션 좌우 패딩:
  모바일: px-4      (16px)
  태블릿: md:px-8   (32px)
  PC:     lg:px-16  (64px)

섹션 상하 패딩:
  모바일: py-16     (64px)
  PC:     md:py-24  (96px)

카드 내부 패딩:
  모바일: p-4       (16px)
  PC:     md:p-6    (24px)

그리드 간격:
  모바일: gap-4     (16px)
  PC:     md:gap-8  (32px)
```

> **핵심: 모바일에서 좌우 패딩 합산이 48px을 넘으면 안 된다.**

---

### 2.2 타이포그래피 스케일

| 용도 | 모바일 | PC | 폰트/스타일 |
|------|--------|-----|------------|
| 페이지 타이틀 | `text-[clamp(48px,10vw,160px)]` | 위와 동일 (clamp) | `font-display font-black italic uppercase tracking-tighter` |
| 섹션 타이틀 | `text-3xl` | `md:text-6xl` | `font-display font-black italic uppercase` |
| 서브 타이틀 | `text-xl` | `md:text-3xl` | `font-display font-black italic` |
| 본문 | `text-sm` | `md:text-base` | `font-sans font-medium` |
| 캡션/라벨 | `text-[10px]` | `text-[10px]` | `font-mono font-bold tracking-[0.2em] uppercase text-text-muted` |
| 스탯 숫자 | `text-4xl` | `md:text-7xl` | `font-display font-black italic` |

---

### 2.3 컬러 사용 규칙

```
배경:   bg-bg-primary (#040404) 또는 bg-bg-secondary (#111111) 만 사용
카드:   bg-white/5 (투명도만, 색상 없음)
텍스트: text-text-primary (흰색) 또는 text-text-muted (60% 투명)
강조:   text-accent (#CCFF00) — 아껴서 사용. 한 섹션에 1~2곳만
보더:   border-divider (white 10%) — 필요한 곳에만, 모든 카드에 붙이지 않기
```

**금지 컬러**: 보라색, 파란색 그라디언트, 핑크, 아무 색이든 디자인 시스템에 없는 것

---

### 2.4 그룹 구분 방법 (중첩 카드 대신)

그룹을 구분할 때 카드로 감싸지 말고 다음을 사용:

| 방법 | 코드 | 용도 |
|------|------|------|
| 간격 | `mb-12 md:mb-20` | 섹션 간 구분 |
| 얇은 라인 | `border-t border-divider` | 같은 섹션 내 그룹 구분 |
| 배경 전환 | `bg-bg-secondary` ↔ `bg-bg-primary` | 섹션 레벨 구분 |
| 라벨 텍스트 | 캡션 스타일 소제목 | 그룹 시작점 표시 |

```
❌ 금지:
<div className="bg-white/5 border border-white/10 rounded-2xl p-6">
  <div className="bg-white/5 border border-white/10 rounded-xl p-4">
    콘텐츠
  </div>
</div>

✅ 허용:
<div className="space-y-6">
  <p className="text-[10px] font-mono ...">SECTION LABEL</p>
  콘텐츠 A
  <div className="border-t border-divider pt-6">
    콘텐츠 B
  </div>
</div>
```

---

### 2.5 이미지 규칙

- `rounded-2xl` 통일 (둥근 모서리는 이 값만)
- `object-cover` 필수
- `loading="lazy"` 필수 (히어로 제외)
- 호버: `group-hover:scale-105 transition-transform duration-700`
- 흑백 기본 → 호버 시 컬러: `grayscale group-hover:grayscale-0`

---

### 2.6 버튼/CTA 스타일

```
Primary CTA:
className="inline-flex items-center gap-3 px-6 py-3
  border border-accent bg-transparent
  hover:bg-accent hover:text-black
  text-xs font-black tracking-widest uppercase
  rounded-full transition-colors"

Secondary (텍스트 링크):
className="group flex items-center gap-2
  text-xs font-black tracking-widest uppercase
  text-text-muted hover:text-accent transition-colors"
```

---

### 2.7 애니메이션 원칙

- **등장**: `y: 40 → 0`, `opacity: 0 → 1`, `duration: 0.8`, `ease: power3.out`
- **Stagger**: `stagger: 0.08` (빠르게, 늘어지지 않게)
- **ScrollTrigger start**: `'top 80%'` (너무 늦지 않게)
- **호버**: CSS `transition-*`만 사용. GSAP 호버 금지 (성능).
- **스크롤 패럴랙스**: 히어로/갤러리에만. 일반 섹션에서 남용 금지.

## 3. 반응형 체크리스트

구현 후 반드시 확인:

- [ ] 375px (iPhone SE)에서 콘텐츠가 잘리지 않는가?
- [ ] 좌우 패딩 합산이 48px 이하인가?
- [ ] 카드 중첩이 1단계 이하인가?
- [ ] 텍스트가 오버플로우 없이 읽히는가?
- [ ] 터치 타겟(버튼/링크)이 44px × 44px 이상인가?
- [ ] 가로 스크롤이 의도치 않게 발생하지 않는가?
- [ ] 이미지가 화면 밖으로 삐져나가지 않는가?

## 4. 코드 작성 시 지켜야 할 것

1. **Tailwind 클래스 순서**: 레이아웃 → 크기 → 패딩/마진 → 배경 → 보더 → 텍스트 → 효과
2. **매직 넘버 금지**: `w-[347px]` 같은 하드코딩 대신 `w-full max-w-sm`
3. **인라인 스타일 최소화**: GSAP 애니메이션 대상이 아니면 Tailwind 사용
4. **max-w-[1440px] mx-auto**: 모든 섹션의 콘텐츠 래퍼에 적용
5. **clamp() 적극 활용**: 큰 타이포는 `text-[clamp(min, preferred, max)]`로
