# 📋 프론트엔드 작업지시서: 접수 사진 다중 업로드 및 저장 연동

이 문서는 대회 참가 접수 시 선수 사진을 2장 이상 업로드하고 백엔드에 안전하게 저장하기 위한 프론트엔드 화면 및 비즈니스 로직 수정 작업지시서입니다.

---

## 1. 개요 및 배경

기존에 1장만 등록 가능하던 접수 사진을 2장 이상 등록할 수 있도록 기능을 확장합니다. 기존 단일 이미지 참조 시스템(채점판 등)이 깨지는 것을 방지하기 위해 아래의 **하이브리드 데이터 적재 방식**을 준수해야 합니다.

- **Firestore**: 기존과 완전히 동일하게 첫 번째로 업로드된 **대표 사진 URL(단일 string)**만 `playerPhotoUrl` 필드에 저장합니다. (다중 배열 필드는 Firestore에 업로드하지 않습니다.)
- **Cloudflare D1**: 전체 다중 사진 URL 리스트를 **`playerPhotoUrls` (string[])** 필드로 전송하여 백업 아카이브에 영속화합니다. (D1 측은 백엔드 API에서 자동으로 문자열 직렬화하여 적재하도록 이미 조치 완료되었습니다.)

---

## 2. 사전 인프라 및 타입 보강 완료 사항
*이미 백엔드 및 공통 타입 부분은 배포 및 수정 완료되어 있어 바로 참조하여 개발하실 수 있습니다.*

1. **D1 데이터베이스 마이그레이션 완료**: `invoices_pool` 테이블에 `playerPhotoUrls TEXT` 컬럼 추가 완료.
2. **백엔드 API 워커 (`ybbf-api-worker`) 배포 완료**: `POST /api/register` 엔드포인트에서 `playerPhotoUrls`를 받아 D1에 저장하는 작업 배포 완료.
3. **공통 타입 정의**: [registration.ts](file:///d:/app2/ybbf/src/types/registration.ts#L64)의 `RegistrationPayload`에 `playerPhotoUrls?: string[];` 필드 추가 완료.

## 3. 프론트엔드 상세 수정 요구사항

### 3.1. 접수 폼 컴포넌트 수정 (`src/pages/RegistrationPage.tsx` 등)
- **UI 개선**:
  - 기존 1개만 업로드 가능했던 이미지 파일 선택창을 **다중 파일 선택(`<input type="file" multiple />`)** 또는 **순차적으로 사진을 여러 장 추가할 수 있는 리스트형 업로드 폼**으로 개편합니다.
  - 업로드 대기 중인 이미지의 썸네일 미리보기와 각각의 '삭제' 버튼을 제공하여 UX를 확보합니다.
- **R2 다중 업로드 연동**:
  - 사용자가 선택한 이미지 파일 리스트에 대해, 루프를 돌며 각각 미디어 워커(`ybbf-media-worker`의 `POST /api/upload?folder=invoices`)를 호출하여 R2 URL들을 배열로 획득합니다.
  - R2 업로드 API 엔드포인트: `${import.meta.env.VITE_MEDIA_API_URL}/api/upload?folder=invoices`

### 3.2. 데이터 전송 페이로드 구성 및 서비스 연동 (`src/services/registrationService.ts`)
- **데이터 구조 가공**:
  - R2 업로드 완료 후 취득한 이미지 URL 배열(`string[]`)이 `urls`일 때, 백엔드 API로 보낼 `RegistrationPayload`를 다음과 같이 구성합니다.
  ```typescript
  const finalPayload: RegistrationPayload = {
    ...formData,
    // 1. 첫 번째 사진을 대표 이미지로 Firestore & D1 공통 호환성 필드에 기입
    playerPhotoUrl: urls[0] || '', 
    // 2. 전체 사진 배열을 D1 백업용 필드에 매핑
    playerPhotoUrls: urls 
  };
  ```
- **제출 함수 호출**:
  - `submitHybridRegistration(finalPayload)` 또는 수정 시 `updateHybridRegistration(invoiceId, finalPayload)`를 호출합니다.

### 3.3. 접수 내역 수정 폼 컴포넌트 수정 (`src/pages/RegistrationEditPage.tsx` 또는 마이페이지 수정부)
- 참가 신청 정보를 수정할 때도 마찬가지로 기등록된 다중 사진 목록(`playerPhotoUrls`)을 표시하고, 추가로 업로드하거나 삭제하여 수정본을 `updateHybridRegistration` 함수를 통해 보낼 수 있게 동일한 구조를 적용해야 합니다.

## 4. 검증 시나리오 (Verification)
1. **다중 업로드 기능 검사**: 3장의 사진을 선택하여 접수를 제출합니다.
2. **Firestore 확인**: Firestore의 `invoices_pool` 문서를 조회했을 때 `playerPhotoUrl` 필드에 첫 번째 대표 사진 URL이 문자열로 정상 저장되었고, `playerPhotoUrls` 배열 필드는 생성되지 않았음을 확인합니다.
3. **D1 확인**: D1 데이터베이스 `invoices_pool` 테이블을 조회했을 때 `playerPhotoUrl`과 `playerPhotoUrls` (JSON 배열 형식 `["url1", "url2", ...]`)이 정상 적재되었는지 확인합니다.
